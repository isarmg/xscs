# XSCS 3.0.0

本次发布包含 v2.0.0 之后的服务端、管理界面、认证和安装工具修复。发行目标为 **Linux x86_64 GNU**，归档内包含服务端、嵌入式 Rust/WASM Web、安装维护工具、许可证、SBOM、来源与完整性材料。

## 主要变化

- 支持同源 HTTP 的本机和局域网登录，以及由 Caddy 等反向代理终止 HTTPS 的部署；保留认证、同源与 CSRF 检查。
- 管理页面采用 ZXS 风格的布局与控件，统一 36px 输入框、圆角和焦点轮廓；客户端绑定区域移到实例信息下方，账号设置页沿用共用样式。
- 新增固定的 `rustdesk` / `one_kvm` 实例类型与跨 backend 授权。One-KVM 视频、HID、ATX 和虚拟媒体仍由设备执行，管理服务仅提供身份、授权与只读诊断。
- 减少授权和心跳路径的重复读取与写入，优化设备 / 任务索引、设备快照和列表查询；保留实时撤权、会话归属和任务持久确认边界。
- Web 功能启动不再等待字体下载，保留字体回退、启动错误与重试反馈；修复阻塞发布检查的 13 项组件调用 Clippy 问题。
- 所需 foundation、协议和安装工具源码随本仓库维护；发行包由精确 annotated tag 构建并生成 SHA-256，不要求从 xcss / xcsc 仓库取得运行时源码。

## 升级前必读

**本版本的数据格式为 v4 / schema revision 4，与旧正式版 v2.0.0 的 v3 数据格式不兼容，因此使用新的主版本号。设备管理协议仍为 v2。**

服务启动不会自动迁移旧库。已经运行当前 v4 开发版本的环境保持现有数据合同；已有确切 v3 数据需先停止服务、保全完整 ROOT 及密钥，再显式离线迁移。不要删除 SQLite 的 WAL / SHM / journal 来绕过检查。

从本版本源码目录执行以下命令，替换为自己的绝对路径，并选择尚不存在的私有备份文件：

```sh
python3 scripts/migrate-v3-v4.py \
  --database /absolute/ROOT/state/xscs.sqlite3 \
  --backup /absolute/private-backups/xscs-before-v4.sqlite3
```

迁移脚本需要同版本源码中的 DDL、基础库 metadata SQL 和 `release.json`；请使用本标签完整源码，而非单独复制脚本。它只接受确切 v3，先备份再事务迁移，保留管理员、实例、安装绑定、凭据、授权、持久任务与审计。已是 v4 时明确拒绝重复迁移；其他旧格式不猜测转换。

完成迁移后按发行包中的安装 / 升级入口替换程序，在同一 ROOT 受控启动并检查 `/readyz`。不必重新创建已有原生实例。也可选择新的 ROOT 初始化独立环境，不自动接管旧凭据和历史。

详细步骤见 [One-KVM 数据格式与升级](https://github.com/isarmg/xscs/blob/v3.0.0/docs/one-kvm.md#数据格式与升级)、[部署与运维](https://github.com/isarmg/xscs/blob/v3.0.0/docs/operations.md)。

## 下载与校验

下载 `xscs-3.0.0-linux-x86_64.tar.gz` 和同名 `.sha256` 后执行：

```sh
sha256sum --check xscs-3.0.0-linux-x86_64.tar.gz.sha256
```

执行载荷前继续核对包内 `share/package.json`、`share/package.sha256` 与文件清单。安装工具不会自动启动或启用服务；核对配置后由管理员启动。

服务端检查与安装生命周期验收不代替 One-KVM 或 XSCC 的物理设备采集、音视频串流与系统权限验收。
