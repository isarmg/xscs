# 原生集成与验收

本轮只修改 xscs/xscc 的 `feat/management-prep` 分支。自定义 RustDesk 源码已复制到 xscc 独立维护，原 RustDesk 仓库未改动。本开发分支不直接替换已部署服务，也不自动接管旧实例或旧状态。

xscc 已接入受保护管理凭据、实例绑定界面、只读诊断、持久执行回执、后台生命周期与授权主机列表。原生会话在加密握手后证明完整安装身份，并持续检查授权；关系撤销、解绑、管理连接断开或租约失效会关闭不再授权的连接。原生密码和本地确认继续生效。

控制端支持 Linux amd64、macOS 26 Apple Silicon、Windows 11 amd64、iOS 26/iPadOS 26 arm64、Android arm64（API 29 起）。被控端支持前三个桌面平台；移动端不启用被控监听或地址上报。客户端与服务端配套升级，移动端在注册前与管理 Hello 时分别检查实例角色。

当前验证包括管理协议与恢复测试、桌面三平台管理检查、移动端管理库交叉检查、Flutter 界面分析、完整 Linux 原生编译，以及 HTTPS/WSS 的双实例管理联调。这些不代替真实设备的音视频、输入、重连、前后台切换、睡眠恢复和系统权限验收。具体记录见 xscc 的 `docs/development.md` 与 `docs/readiness.md`。

硬件设备、编码器、编码格式、画质和帧率由原生主控端选择并与被控端协商。服务端不保存或下发这些设置。正式安装包采用 `2.0.0` 稳定版号，仍需通过精确源码绑定的安装生命周期与发行合同验证，见 [开发验证](development.md)。当前契约不匹配时拒绝升级并保留原环境；新结构通过专用安装流程在新的数据目录初始化，不转换旧状态或重新解释旧任务。
