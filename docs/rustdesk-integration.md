# 等待 RustDesk 稳定后的接入

本轮只改变 xscs/xscc 的 `feat/management-prep` 分支，RustDesk 源码不变。本分支目前不应替换已部署服务。

先记录稳定 RustDesk 的完整 revision，并完成 Windows 主机与观看端构建、正常串流、音频、输入和重连验收，再按实际支持范围验证 Wayland/macOS。

之后统一工具链和依赖，给 RustDesk 添加 xscc 库依赖；由控制端和被控端分别绑定同角色实例，提供 NativeHost、NativeJournal、配对 UI 和受保护管理凭据，在已有 runtime 启动管理任务并参与退出流程。本库使用 Rust 1.99；接入时核对稳定 RustDesk 的工具链与锁定依赖，完成原生构建验证。

验证新建绑定、响应丢失恢复、凭据撤销、服务/桌面用户切换、断线执行与结果重放、保护存储失败、睡眠恢复和正常退出。替身诊断和网页测试不代替原生运行证明。

原生接入必须订阅 xscc 授权观察、上报被控端实际监听地址，并将对端的已认证安装身份与授权列表绑定；不能按来源 IP 判断权限。规则撤销、列表租约到期或管理连接断开时，宿主停止接受新会话，并终止不再授权的既有会话。原生密码/密钥与授权证明、运行时会话撤销及媒体性能仍需在稳定 RustDesk 中验收。

硬件设备、编码器、编码格式、画质和帧率由 RustDesk 主控端选择并与被控端协商。服务端不维护这些具体配置，也不提供远程修改这些配置的命令。正式升级前单独制定旧状态归档与显式迁移方案；不重新解释旧任务。
